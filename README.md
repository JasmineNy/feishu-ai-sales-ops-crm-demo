# 飞书销售运营轻量 CRM｜跟进记录闭环

一个基于飞书多维表格搭建的销售运营练习作品，用虚拟数据演示商机跟进任务如何被记录、明确责任、识别到期并支持复盘。

## 项目背景

在渠道销售和生态经营中，活动或日常沟通会产生大量后续动作。信息分散在会议记录、聊天和个人待办里，负责人、截止时间与当前进度不容易统一查看；管理者也难以快速发现哪些高意向商机尚未跟进、哪些行动已经逾期。

这个原型从“跟进记录”切入，把商机关系、负责人、下次行动、状态和到期情况放进同一条业务链路。销售可以看到自己接下来要做什么，管理者可以区分正常推进、已经逾期和已结束的任务。

## 解决的问题

- 跟进任务缺少统一记录位置，容易遗漏或重复沟通。
- 责任人和商机归属脱节，交接时难以明确谁来推进。
- 只记录历史沟通，缺少下一步动作、截止时间和完成状态。
- 管理者需要手工筛选，才能找到逾期任务和近期待办。
- 活动线索进入销售跟进后，过程状态难以回收和复盘。

## 功能与业务逻辑

### 1. 数据对象如何关联

系统围绕客户、伙伴、商机和跟进记录组织数据。客户与伙伴信息提供经营背景，商机记录承载销售机会，跟进记录承载围绕商机发生的一次具体动作。目标与预测、销售分配规则、销售运营驾驶舱提供目标管理和经营分析的扩展位置。

跟进记录采用“一条记录对应一次跟进任务”的粒度。同一商机可以关联多条跟进记录，按时间形成沟通历史；每条待办都必须能回答四个问题：跟进谁、谁负责、下一步做什么、什么时候完成。

### 2. 字段如何支持动作

一条跟进记录保留沟通日期、沟通动作、进展、风险、下次动作和关联商机。运营字段将记录转成可执行任务：

| 字段 | 用途 |
| --- | --- |
| 下次行动时间 | 给下一步动作设定时间边界，支持安排优先级 |
| 跟进负责人 | 当前测试阶段按关联商机 Owner 匹配虚拟负责人，便于责任追踪 |
| 跟进状态 | 待处理表示仍需行动；已完成表示动作已执行；已取消表示该动作不再推进 |
| 到期标记 | 到期自动化触发后更新为已到期，方便识别需要检查的记录 |

### 3. 状态与到期如何判定

“到期”描述时间条件，“待处理/已完成/已取消”描述任务状态。两类字段一起使用，避免把所有历史日期已过的记录都误判成逾期：

| 跟进状态 | 到期标记 | 运营解释 |
| --- | --- | --- |
| 待处理 | 未到期 | 未来待办，按计划推进 |
| 待处理 | 已到期 | 逾期待办，需要负责人更新进展或调整计划 |
| 已完成 | 已到期 | 已完成的历史任务，不计入逾期待办 |
| 已取消 | 已到期 | 已取消的任务，不计入待办或逾期 |

当前已配置的到期自动化针对“下次行动时间到达”更新到期标记。负责人维护真实沟通进展并更新任务状态。这样自动化负责稳定、明确的时间判断，销售负责业务判断和实际结果记录。

核心闭环：

```text
活动/日常沟通产生后续事项
        ↓
将跟进动作关联到对应商机
        ↓
按商机 Owner 匹配负责人，填写下一步动作和期限
        ↓
到期自动化更新到期标记
        ↓
负责人更新进展和任务状态
        ↓
按负责人、状态、时间和商机复盘执行情况
```

### 4. 一个业务场景例子

渠道活动后，销售与某家虚拟企业负责人沟通，确认对方希望进一步了解解决方案。活动人员或销售在跟进记录中关联对应商机，写入“预约方案沟通”及约定时间，并按该商机 Owner 匹配虚拟负责人。到期前，这条记录属于未来待办；到期后仍为待处理，系统将其标记为已到期，负责人据此补充联系结果、下一步安排或取消原因。活动运营者随后可以回看该场活动产生的待办是否有人接手、进展是否回收。

这条链路把活动线索交接落到可检查的动作层面。对销售来说，它是一份个人任务清单；对销售运营来说，它提供了发现漏跟进、推动责任闭环和回收过程信息的基础数据。

### 5. 管理者可以据此观察什么

基于现有字段可以形成以下经营观察口径：

- **待办存量：**当前仍待处理的任务数量，按负责人、区域或商机查看。
- **逾期存量与逾期率：**待处理且已到期的任务数量及其占待处理任务的比例。
- **任务完成情况：**已完成、待处理、已取消的数量与变化趋势。
- **行动及时性：**从计划时间到实际更新状态的间隔；后续可补充完成时间字段以准确计算。
- **商机跟进连续性：**重点商机是否持续有下一步动作，是否出现长时间无更新。

当前原型以记录和到期标记为主，以上指标属于基于现有数据结构可延展的经营分析方向。若要计算准确的完成及时率、商机阶段转化率或赢单率，需要增加实际完成时间、商机阶段变化历史等字段，并统一统计口径。

## 创建思考

我从一线渠道经营中的真实管理问题出发，先把销售跟进拆成可执行的最小单元：一条商机、一位责任人、一个明确动作、一个完成期限和一个状态。随后再补上到期识别与过程视图，让数据能支持每天的跟进安排和周期复盘。

字段设计强调责任可追溯、动作可检查、状态可统计。负责人根据商机 Owner 匹配，降低跨表核对成本；截止时间与任务状态配合，形成清楚的待办定义。自动化先处理确定性规则，销售补充实际沟通信息，管理者使用统一口径复盘。

设计过程遵循三个判断：

1. **先管理动作，再扩展预测。**先保证每个商机的下一步有人负责、有明确时间，销售过程数据才有分析价值。
2. **把计划与结果分开记录。**截止时间表达计划，状态表达执行结果；需要准确评估及时性时，再加入实际完成时间。
3. **让规则可解释、可修正。**到期标记由日期规则更新，业务人员可通过更新状态体现完成或取消，避免自动化替代销售判断。

## 当前原型范围

- 飞书多维表格作为记录与视图载体。
- 关联商机、负责人、下次行动时间、跟进状态和到期标记等字段。
- 到期触发规则用于更新到期标记。
- 80 条跟进记录使用虚拟演示数据，分布为 32 条已完成、16 条待处理且已到期、24 条待处理且未到期、8 条已取消；另保留 1 条独立的自动化测试记录。
- 当前负责人是虚拟单选项，按对应商机 Owner 匹配；没有连接真实飞书人员账号。
- 当前自动化用于更新到期标记；负责人消息通知、管理升级、AI文本分析和生产 CRM 集成尚未接入。
- 当前作品展示轻量原型和业务流程设计，不代表已连接企业 CRM、真实客户数据或生产环境通知系统。

## 后续可扩展方向

1. 负责人改为飞书人员字段，并与商机 Owner 保持一致。
2. 建立“逾期待办”“未来 7 天待办”“按负责人跟进”等日常工作视图。
3. 补充商机阶段准入标准、下一步行动模板和丢单原因。
4. 增加 Pipeline 阶段、预计金额、预计成交时间和 Forecast 汇总。
5. 在权限与通知对象确认后，再扩展负责人提醒和管理升级机制。
6. 接入 AI 辅助生成跟进摘要、待确认信息和行动建议，并保留人工复核。

## 项目价值

这个作品体现了我把伙伴经营与销售运营问题转为字段、规则和视图的能力：从业务场景梳理、数据结构设计，到状态定义、自动化规则和复盘路径，先让过程透明、责任明确，再逐步扩展预测分析与 AI 辅助能力。
