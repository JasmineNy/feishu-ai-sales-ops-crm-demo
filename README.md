# 飞书销售运营轻量 CRM｜跟进记录闭环

一个基于飞书多维表格搭建的销售运营练习作品，用虚拟数据演示商机跟进任务如何被记录、分配、提醒和复盘。

## 项目背景

在渠道销售和生态经营中，活动或日常沟通会产生大量后续动作。信息分散在会议记录、聊天和个人待办里，负责人、截止时间与当前进度不容易统一查看；管理者也难以快速发现哪些高意向商机尚未跟进、哪些行动已经逾期。

这个原型从“跟进记录”切入，把商机关系、责任人、下次行动、状态和到期情况放进同一张可运营的数据表，形成轻量的销售任务清单和过程视图。

## 解决的问题

- 跟进任务缺少统一记录位置，容易遗漏或重复沟通。
- 责任人和商机归属脱节，交接时难以明确谁来推进。
- 只记录历史沟通，缺少下一步动作、截止时间和完成状态。
- 管理者需要手工筛选，才能找到逾期任务和近期待办。
- 活动线索进入销售跟进后，过程状态难以回收和复盘。

## 功能与业务逻辑

每条跟进记录关联一条商机，并保留沟通日期、动作、进展、风险和下次动作等信息。新增的运营字段包括：

| 字段 | 用途 |
| --- | --- |
| 下次行动时间 | 形成明确的下一步期限 |
| 跟进负责人 | 当前测试阶段按关联商机的 Owner 匹配虚拟负责人 |
| 跟进状态 | 区分待处理、已完成和已取消 |
| 到期标记 | 展示未到期或已到期状态 |

核心闭环：

```text
商机与沟通记录关联
        ↓
明确负责人、下一步动作和截止时间
        ↓
待处理任务进入销售跟进清单
        ↓
到期自动化检查日期并更新到期标记
        ↓
负责人更新进展，管理者按状态复盘
```

设计上将“到期”和“逾期未跟进”分开判断：记录到期后，自动化可更新到期标记；只有“待处理且已到期”的记录才属于逾期待办。已完成或已取消的记录即使日期已过，也不应进入逾期待办统计。

## 创建思考

我从一线渠道经营中的真实管理问题出发，先把销售跟进拆成可执行的最小单元：一条商机、一位责任人、一个明确动作、一个完成期限和一个状态。随后再补上到期识别与过程视图，让数据能支持每天的跟进安排和周期复盘。

字段设计强调责任可追溯、动作可检查、状态可统计。负责人从商机 Owner 映射，降低跨表核对成本；截止时间与完成状态配合，避免仅凭日期判断任务是否仍需处理。自动化先承担确定性规则，业务人员负责更新实际进展。

## 当前原型范围

- 飞书多维表格作为记录与视图载体。
- 关联商机、负责人、下次行动时间、跟进状态和到期标记等字段。
- 到期触发规则用于更新到期标记。
- 80 条跟进记录使用虚拟演示数据，分布为 32 条已完成、16 条待处理且已到期、24 条待处理且未到期、8 条已取消；另保留 1 条独立的自动化测试记录。
- 当前负责人是虚拟单选项，按对应商机 Owner 匹配；没有连接真实飞书人员账号。
- 当前作品展示轻量原型和业务流程设计，不代表已连接企业 CRM、真实客户数据或生产环境通知系统。

## 后续可扩展方向

1. 负责人改为飞书人员字段，并与商机 Owner 保持一致。
2. 建立“逾期待办”“未来 7 天待办”“按负责人跟进”等日常工作视图。
3. 补充商机阶段准入标准、下一步行动模板和丢单原因。
4. 增加 Pipeline 阶段、预计金额、预计成交时间和 Forecast 汇总。
5. 在权限与通知对象确认后，再扩展负责人提醒和管理升级机制。
6. 接入 AI 辅助生成跟进摘要、待确认信息和行动建议，并保留人工复核。

## 项目价值

这个作品体现了我把伙伴经营与销售运营问题转为字段、规则和视图的能力：从业务场景梳理、数据结构设计，到状态定义、自动化规则和复盘路径，先让过程透明、责任明确，再逐步扩展预测分析与 AI 辅助能力。
